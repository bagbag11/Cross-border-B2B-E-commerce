# 货代数据审查修复

对飞书多维表「物流询价数据库」中的货代路线和计费规则，对照源文件逐字段审查、按优先级修复、回读验证。

## 何时触发

用户要求审查/核查/复核/修复多维表中的货代数据，典型场景：
- "审查 XX 货代的路线信息和计费规则是否符合源文件"
- "核查 XX 的价格是否正确，有没有虚假报价"
- "修复 XX 的错误数据"
- "XX 的尺寸限制/附加费/报关费字段缺失，补录一下"
- "XX 有无源路线/虚假价格，处理一下"

## 前置条件

- 目标多维表：飞书 Base「物流询价数据库」，含**路线信息表**和**计费规则表**两张数据表。
- 源文件：货代报价 Excel 或截图，由用户提供（上传到任务评论或飞书云盘）。
- 需 `get_skills("larksuite-cli-guide")` 后使用 `lark-cli base` 操作多维表。

## 核心流程（5 步）

### 第 1 步：拉取多维表全量数据

用 `lark-cli base +table-get`（或 `+records-list` 分页）拉取目标货代的全部路线记录和计费记录。按货代名称或线路ID前缀（如 YH-/ASD-/XP-）筛选。

关键：**先记录当前数据状态快照**（路线数、计费记录数、关键字段非空率），作为审查基线。

### 第 2 步：解析源文件

根据源文件类型解析：
- **Excel**：用 `openpyxl` 逐 sheet 读取，识别报价表结构（表头行位置、路线行范围、计费档位列）。
- **截图**：用 `file read` 模式识别截图内容，手动映射到多维表字段。

提取出源文件中的：路线列表（名称/邮编/时效/城市等）、计费规则（重量档位/单价/最低收费）、附加费用（报关费/超长附加费/超重条件）、尺寸限制（最长边/围长/三边和）。

### 第 3 步：逐字段回源比对

将多维表记录与源文件逐字段比对，按错误类型分类。详细比对规则见 [references/audit-rules.md](references/audit-rules.md)。

**比对维度：**
1. **路线层面**：路线数是否一致、路线名称/邮编/城市/时效/服务类型/清关模式是否正确
2. **价格层面**：每条路线每档单价是否与源文件一致、有无虚假价格、有无系统性错位
3. **计费结构**：rule_type 是否正确（unit_price/range_price/first_continued）、重量档位边界是否正确
4. **附加费用**：报关费/超长附加费/超重条件/最大长度限制是否缺失
5. **尺寸限制**：最长边/围长/三边和是否缺失或错误
6. **路线状态**：无源路线是否应停用、真实路线是否被误停用

### 第 4 步：按优先级修复

修复严格按 P0→P1→P2→P3 顺序执行。**不可逆操作（删除/批量替换）执行前必须先备份**，并向用户确认方案。

| 优先级 | 含义 | 典型问题 |
|---|---|---|
| **P0** | 数据本质错误，影响询价准确性 | 虚假价格、系统性价格错位、计费方式互串、价格结构错误、时效严重偏差 |
| **P1** | 字段缺失或错误，影响完整性 | 尺寸限制空值、附加费缺失、报关费缺失、服务类型/清关模式错误 |
| **P2** | 档位边界/口径偏差 | 重量档位边界值不一致、计费单位不统一、最低收费规则缺失 |
| **P3** | 信息完善 | 运输类型/支持物品类型/邮编范围补充 |

**修复操作规则：**
- **无源路线**：停用（`是否启用` → 停用），不删除
- **虚假价格**：删除该计费记录，用源文件正确价格替换
- **字段补录**：直接更新对应字段
- **批量操作**：按 ≤200 条/批执行，每批完成后回读确认
- **字段选项不存在时**：先 `lark-cli base +field-update` 新增选项再写入

### 第 5 步：回读验证

修复完成后全量回读，验证：
- 路线数/计费记录数是否符合预期
- 抽样 ≥10 条回读关键字段，确认与源文件一致
- 扫描异常：零空价、零零价、价格范围合理性
- 输出修复报告（修改前/后对比、执行明细、验证结果）

## 用户确认的关键规则（已固化）

这些规则来自实际审查中用户明确的决策，后续执行时直接遵循：

1. **体积系数固定为 6000**，不调整
2. **无源路线 → 停用**（不删除），在「是否启用」选停用
3. **虚假价格 → 删除**该计费记录
4. **计费单位不动**（即使不统一也不修改）
5. **价格异常判定以源文件真实价格为依据**，不按相邻区间推测
6. **重复判定标准**：同一行全部字段完全相同才算重复（邮编不同 = 合理展开）
7. **CBM 最低收费**：无特别说明默认 0.5CBM；有价格分档规则则按分档（<1500/CBM 按 1CBM，≥1500 按 0.5CBM）
8. **支持物品类型**按四大类标准：普货/带电带磁/纯电/危险品（源文件未提及则留空）
9. **截图优先于源 Excel**：当用户提供截图修正时，以截图数据为准

## 常见错误模式（实战总结）

| 错误模式 | 表现 | 根因 | 修复方式 |
|---|---|---|---|
| 用错源 sheet | 路线数远超预期、价格系统性偏低 | 导入时选了错误的 sheet（如细粒度价格表而非路线总览） | 确认正确 sheet，删除错误数据，按正确 sheet 重建 |
| 系统性价格错位 | DB 价格是源文件其他路线的价格 | 导入时路线-价格对应关系错位 | 按路线ID逐一回源修正单价 |
| 虚假价格 | 价格在源文件完全不存在 | 导入时编造或四舍五入 | 删除记录，用源文件真实价格替换 |
| 真实路线被误停用 | 源文件有但 DB 中为停用状态 | 上一轮误判为"无源" | 启用并修正字段 |
| 字段系统性缺失 | 某字段全空但源文件有值 | 导入时未提取该字段 | 批量补录 |
| 尺寸限制套错规格 | 东欧路线套了波兰规格 | 按渠道分组时混用 | 按渠道逐组核对源文件 |

## 注意

- 删除/批量替换属不可逆操作，执行前必须备份（`lark-cli base +table-get` 导出 JSON）并向用户确认
- 每批操作后回读确认，避免批量错误累积
- 修复报告按「修改背景 → 当前痛点 → 修改结果 → 执行明细 → 回读验证」结构输出
- 数据来源和统计口径（自然周）须在报告末尾标注
